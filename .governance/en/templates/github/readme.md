# README Publishing Template

Write for readers, based on actual code, tests and published artifacts. Confirm project purpose, technologies, compatible versions, installation, usage, licensing, and only the optional assets or comparisons that really exist. Investigate repository facts instead of repeatedly asking about them. Ask for decisions that change public contracts or licensing.

## Suggested structure

```markdown
# Project Name

![Version](https://img.shields.io/badge/version-1.2.0-blue)
![License](https://img.shields.io/badge/license-MIT-green)

[中文](#中文) | [English](#english)

## 中文

### 關於
Describe the implemented purpose.

### 功能
List actual features.

### 安裝
Provide verified requirements and commands.

### 使用方式
Include an executable example.

### 授權
Point to LICENSE.

## English

### About
State the actual purpose and scope.

### Features
List implemented capabilities.

### Installation
Use verified steps.

### Usage
Show an executable example.

### License
Refer to LICENSE.
```

These version strings are placeholders; replace them with facts from the project before publishing. Screenshots, demos, compatibility charts and comparisons are optional and only included when supported by evidence. Keep facts equivalent across language sections, distinguish product version from compatibility versions, use a valid SPDX license identifier and check every example and link.
