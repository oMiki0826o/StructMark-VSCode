# Discord Release Templates

Keep announcements concise and factual. Include only verified repository URLs, release pages and download artifacts. Prefer a few recent versions and a releases index over an exhaustive history.

## General software and tools

```markdown
**Project Name**
One-sentence summary of the shipped project.

---

Explain the use case, supported environment and meaningful limitations.

Main features:
- Implemented feature one
- Implemented feature two

Technology: `Python` or the actual stack

- GitHub repository: [Project Name](https://example.com/repository)
- Latest release: [v1.0](<https://example.com/release-file>)
- All releases: [Releases](https://example.com/releases)
```

Replace the illustrative URLs with real destinations; never ship placeholders as if they were actual release links. Add one or two screenshots only when they exist.

## Minecraft redstone and structure releases

Use an author line, exact compatible game version, a short two-line introduction, a compact list of specific features, and grouped operating notes. Notes should name the relevant component, the required behavior and what can go wrong. Add a real repository/release section between features and notes only if published files exist.

Check the Discord message length, version consistency and technical accuracy before posting.
