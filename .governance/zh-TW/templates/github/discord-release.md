# Discord 發布文案模板

發布內容應簡短、方便閱讀且連結可用。只引用真實的 Repository、Release 與下載檔，不得填入推測網址。若版本紀錄很多，只列出有價值的近期版本並附完整 Releases 頁面。

## 一般工具、模組與軟體

```markdown
**作品名稱**
一句話介紹這個作品。

---

用兩三句說明用途、支援平台及限制。

主要功能：
- 功能一
- 功能二
- 功能三

技術：`Python`、`Java` 或專案實際技術

- GitHub 倉庫：[作品名稱](https://example.com/repository)
- 最新版本：[v1.0](<https://example.com/release-file>)
- 所有版本：[Releases](https://example.com/releases)
```

範例網址不得直接發布；連結必須換成已確認存在的真實網址。必要時可附 1–2 張展示圖。不強制每則文案都含圖片。

## Minecraft 紅石機器或建築作品

```markdown
作者：`作者名稱`
版本：`Minecraft Java 相容版本`
---
> 一句話說明核心特色
> 一句話說明適合的使用情境
---
## 特點：
- `特點一`
  -# 可選：具體說明這個特點帶來的效果。
- `特點二`

## 注意：
- 整體
  -# **關鍵元件** 必須維持指定狀態，否則會出現可確認的問題。
- 輸出端
  -# **對應容器** 必須在指定位置，原因與後果應具體說明。
```

如確實提供 GitHub 檔案下載，可將真實倉庫、最新版本及 Releases 連結放在「特點」與「注意」之間。若沒有發行檔，省略下載區塊。技術補充行及注意分類依作品實際需求調整，避免只堆砌關鍵字。

## 驗證事項

- 版本名稱與下載檔一致，連結指向正確版本。
- 文字不宣稱未驗證的功能、效能及相容性。
- 不複製超過 Discord 單則訊息限制的龐大版本清單。
- 產品特有的發布格式可以保留，但不要讓模板凌駕安全與事實性規則。
