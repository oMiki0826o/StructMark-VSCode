# StructMark v2 整合與穩定化設計

狀態：以使用者先前核准的 v2 目標與本次「完成能做到的所有項目、交付兩份 ZIP」為實作依據。這是 v2 候選版本的驗收規格，不等同正式版本承諾。

## 需求與界線

- 為 StructMark 語言核心與獨立 VS Code 倉庫交付**兩份可檢查、完整的來源 ZIP**。
- 保留 v1.6 相容性；v2 使用唯一共用實作，不要以兩份各自演化的 Parser 作為正式介面。
- v2 必須提供指令正規化、結構表格、基本型別驗證、識別符參照、跨文件檢查、行內格式、安全 HTML 輸出與 CLI。
- 新增的功能都要有自動測試。既有網站和 VS Code 依賴無法離線取得時，要明確記錄未通過的驗收，不能假裝「無 bug」。
- 保留原有 v1.x 網站文件內容並為 v2 新增正確的說明，避免把尚未驗證的新版 API 套進舊教學。

## 選擇的架構

1. `src/v2/` 為 v2 可共用 ESM 語言引擎；`experimental/v2/core.mjs` 僅做舊測試相容匯出。
2. `bin/sm2.mjs` 從同一模組提供檢查、AST、格式化、HTML 與工作區檢查。語法錯誤要有非零退出碼。
3. 網站 Playground 提供可明確選擇的 v2 模式，不默默改變 v1.6 文件語意。
4. LSP 透過同一 v2 引擎取得診斷、符號與參照；VS Code 啟動編譯後的 Server，並以打包腳本產生正確的目錄。
5. 狀態紀錄、conformance 案例、工程決策與測試報告納入 ZIP。

## 不在此輪假設已證明的部分

- 無法對所有輸入證明完全沒有錯誤。
- 無法在無 npm Registry、VS Code 主程式的環境下聲稱站台 Build、VSIX 安裝及實際 Editor 互動驗證通過。
- 沒有真實 Tokenizer 執行結果時，不可聲稱較 Markdown 或 @Doc 省 Token。

## 驗收方法

Node.js v2 語言測試、CLI 端對端測試、惡意輸入測試、文件例子校驗、既有命令可執行部分之測試、ZIP CRC、輸出 SHA-256；記錄每個命令與明確限制。
