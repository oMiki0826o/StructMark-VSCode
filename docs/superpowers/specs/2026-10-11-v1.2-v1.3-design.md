# StructMark 1.2–1.3 設計與交付規範

版本：2026-10-11　狀態：實作規格

## 目標與原則

在既有 v1.1.1 完整程式上整合 v1.2（開發者工具、Playground、可操作文件）與 v1.3（工作區參照、文件搜尋、測試強化）功能，不更換正式副檔名 `.sm`，不改寫既有語法。完整來源 ZIP 為交付品，不直接推送 GitHub。

網站保持米白、墨綠的日式極簡設計，沒有 AI 插畫、漸層裝飾。本文只規範實際可完成並可驗證的內容；完整版 CSL、CommonMark、LaTeX 與增量解析不列入完成承諾。

## 元件與介面

1. `src/visitor.ts`：以遍歷而非變更語法樹的 API 讀取 Document、BlockNode、InlineNode；提供進入節點、回傳 false 略過子樹，支援選擇跳過受保護內容。
2. `bin/structmark.mjs`：公開 Node.js CLI。`check`、`render`、`format`、`convert`、`ast`、`workspace` 子指令。`--output` 寫入新檔案；`format --write` 才可修改原檔；stderr 診斷；可機器處理的 JSON 結果與非零退出碼。
3. `src/workspace.ts`：不依賴 Node 的參照解析與工作區索引；路徑基於 POSIX 相對路徑，阻止跳出根目錄，ID 採 NFC；與 `validateWorkspace` 共用。
4. `apps/site`：Playground 範例選擇、HTML / AST 切換、行號診斷定位；文件搜尋使用 build-time 產生索引，且在瀏覽器端進行，不需要後端。
5. `src/markdown.ts`：對語義降級作明確診斷，改善匯出特殊字元，增加已支援子集的 round-trip 測試。`formatSource` 繼續採安全、保守模式，不宣稱 AST 無損重排。
6. 文件、CI 與測試：中英文使用說明、版本紀錄、跨文件測試、CLI 子程序測試及效能基準。若外部依賴不可取得，必須揭露未執行的測試。

## 錯誤處理

CLI 使用 0 正常、1 診斷/轉換失敗、2 操作參數錯誤；不得把失敗的輸出默默覆蓋原檔。工作區參照錯誤包含檔案名稱與實際位置，保留既有 `MMK-S005` 代碼。安全 HTML 由既有 Renderer 處理，不把原始輸入當成可信任 HTML。

## 檢查

TDD：針對每項可觀察行為先加入失敗測試，再修正。執行 `npm test`、`npm run fuzz`、`npm run benchmark:perf`、`cd apps/site && npm run build`；若依賴無法取得，記錄原因，另外執行能使用現有環境驗證的子集。
