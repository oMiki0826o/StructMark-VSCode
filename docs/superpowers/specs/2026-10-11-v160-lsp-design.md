# StructMark v1.6.0 — LSP 與 VS Code 擴充套件設計

日期：2026-10-11　狀態：待使用者審閱；尚未實作

## 目的與交付

從既有 v1.5.0 核心建置獨立 TypeScript Language Server，提供 VS Code 使用，並保留日後供其他 LSP 編輯器使用的協定介面。最後分別交付完整 StructMark 原始碼 ZIP 與可獨立建置的 VS Code 擴充套件 ZIP。維持現有 `.sm` 語法、AST 相容性及網站視覺。

## 架構

- `src/`：既有 Parser、AST、Semantic、Workspace，維持唯一解析來源。
- `packages/language-server/`：Node.js LSP server，使用 `vscode-languageserver` 與 `vscode-languageserver-textdocument`，以 stdio 通訊；不依賴 VS Code API。
- `packages/vscode/`：Extension client、`syntaxes/structmark.tmLanguage.json`、`language-configuration.json`、snippets；以 `vscode-languageclient` 啟動 server。
- 網站 `apps/site/`：保留現有 Playground 與雙語文件，新增編輯器安裝與疑難排解文件。

## v1.6.0 行為規格

1. **文件同步**：`textDocument/didOpen`、`didChange`、`didClose`；以 URI 管理文件；支援 UTF-16 LSP 位置轉換，包含 emoji 與非 BMP 字元。
2. **Diagnostics**：開啟或變更時使用現有核心解析及驗證；關閉時清除診斷；避免舊版本的非同步結果覆蓋新結果；不執行文件中的指令。
3. **Completion**：在合法上下文提供既有 `.sm` 語法與指令名稱；不猜測不存在的語法或屬性。
4. **Hover**：顯示既有語法的簡短說明與範例；不得讀取不受信任路徑。
5. **Document Symbols**：根據 AST 標題產生階層式大綱，來源範圍可供跳轉。
6. **Definition/References**：先支援同文件 ID；跨文件 `.sm#id` 使用 Workspace Index，限制在工作區根目錄內；不可穿越 `../` 到工作區外；無法解析時回傳空結果而非例外。
7. **VS Code UX**：語言辨識、語法著色、括號設定、基本 snippets、啟停 client；語言伺服器異常時可恢復，不使編輯器崩潰。
8. **相容性**：核心 API 不因編輯器需求產生 VS Code 相依；現有 CLI、網站及公開 Parser 行為不變。

## 安全與效能

- 對檔案 URI 解碼、正規化、根目錄邊界與符號連結做檢查；外部參照不能任意讀取。
- 不自動執行 `.sm` 文件內嵌內容；HTML 預覽沿用現有安全 Renderer。
- 每次文字變更僅解析受影響文件，Workspace Index 以文件版本與變更事件失效；不每次按鍵掃描全倉庫。
- 大文件與大量診斷需有上限；未知或不支援的語法不造成 server 崩潰。

## 治理與文件

以 `oMiki0826o/AI-Development-Governance` 現行 README 的分類為基準：Rule 為權威來源、Workflow 決定步驟、Gate 提供驗證、Template 提供格式、Docs 以自然語言解釋。實作前須再讀實際 Rule 與 Gate 檔案，逐條建立可追蹤對照，不以 README 摘要假裝已完成全面符合。使用者文件與 Agent 規範分離；雙語文件一致性檢查納入 CI；`VALIDATION.md` 必須揭露未驗證的建置或功能。

## 驗收

- 真實相依套件下 Core 測試與網站建置通過。
- LSP JSON-RPC 整合測試涵蓋 open/change/close、UTF-16、diagnostics、completion、hover、symbols、definitions、references、URI 安全。
- VS Code 擴充套件可封裝與啟動，使用真實 server；版本均為 1.6.0。
- 兩個 ZIP 各自完整、CRC 與 SHA-256 可驗證，沒有 node_modules、金鑰、暫存檔；測試限制記錄於 VALIDATION。

## 非目標

v1.6.0 不實作 Rename、Code Actions、語義著色、完整 CommonMark、增量 Parser 或正式發布到 VS Code Marketplace。LSP 將保留擴充點，但不提前加入未使用的抽象層。

## 待審閱決策

- Language Server 放在主專案 `packages/language-server/`，VS Code Client 放在 `packages/vscode/`，第二個 ZIP 為可獨立建置的 Extension 原始碼包（包含建置所需的 server 與 core 發布產物或可重現的本機建置步驟）。
- 跨文件參照先以工作區內 `.sm#id` 為界；不支援網路 URI。
