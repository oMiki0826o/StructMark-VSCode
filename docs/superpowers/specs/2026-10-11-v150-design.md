# StructMark v1.5.0 — Design and Acceptance Criteria

## Context
The user's last approved roadmap described v1.3.1 stability, v1.4.0 Playground AST exploration, and v1.5.0 workspace/format-conversion improvements. The source of truth is the supplied complete v1.3.0 ZIP. This is a maintenance and developer-experience upgrade, not a syntax-breaking language version.

## Constraints
- Preserve existing `.sm`, core AST `version: "1.1"`, browser-safe core, public APIs and simple Japanese-minimal site design.
- No invented complete CommonMark/CSL/LaTeX implementation claims.
- CLI never overwrites existing files unless the explicit `format --write` flag is supplied; this path must use a same-directory atomic replacement with cleanup on failure.
- Relative workspace references must report referring file, target, and line/column; no path traversal outside the workspace.
- Playground remains a statically exportable, client-side-only Next.js site; new AST Tree must use existing AST and allow selecting corresponding editor span.
- Responsive header must remain single line for mobile homepage title.
- Use tests first for each behavior; report dependency-related build limitations clearly.

## Components
1. **CLI safety and diagnostics (v1.3.1)** — atomic `format --write`, structured cross-document errors, deterministic CLI exit codes.
2. **Workspace index (v1.5)** — browser-safe `buildWorkspaceIndex` constructs a path-and-ID index and exposes structured references/diagnostics; `validateWorkspace` remains backwards compatible.
3. **AST Tree (v1.4)** — a client UI using existing `parseDocument` output, concise expandable node information, keyboard-accessible buttons, precise source selection and HTML/JSON views. No external editor dependency.
4. **Conversion safety** — preserve existing output, add loss warnings and targeted regressions; no promise of complete CommonMark equivalence.
5. **Release hygiene** — version/changelog/docs/test matrix and end-to-end packaging; no pushing/publishing automatically.

## Success criteria
- CLI tests verify both successful atomic write and refused clobber.
- Workspace tests verify file-precise cross-document diagnostics and normalized paths.
- AST Tree tests verify nested block, list, inline, and source ranges; click selects relevant source span.
- Core suite, site suite, fuzz, perf, Next.js build and browser tests run with installed dependencies where available. Failures due to missing dependencies are documented, not hidden.
- The output is one complete source ZIP with no node_modules or generated output.
